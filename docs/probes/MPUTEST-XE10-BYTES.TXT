NOTE MPUTEST (tools/hwprobe/mputest): MPU-401-family MIDI card probe. Decode with
NOTE mputest_decode.py; its README lists the sources for these expectations.
NOTE The core models the MPU-PC98II as NP2kai does: every intelligent-mode command
NOTE is ACKed FE at once; 0xFF AND 0x3F each send 16 x Bn 7B 00 (all notes off) on
NOTE MIDI OUT; in UART mode only 0xFF is answered (ACK, no burst); BUSY (bit 6) =
NOTE its 32-byte output queue half full or a byte waiting for room; base E0D0,
NOTE IRQ6 only; no MIDI IN.
NOTE Expected to DIFFER on a real card: ACK latency (the card's own CPU), how long
NOTE DRR stays busy per byte, whether 0xFF/0x3F put bytes on MIDI OUT (the Roland
NOTE MPU-401 manual names none), the UART-mode 0xFF (the manual: NO ACK), how many
NOTE blind /RAW bytes survive. MPU-PC98 (original): base E0D0 and INT2 (IRQ6) fixed,
NOTE tape sync; MPU-PC98II: 16 bases C0D0-FCD0 by DIP switch, INT0/1/2/5 (IRQ
NOTE 3/5/6/12) by jumper, default E0D0/INT2. MIDI IN bytes show as extra= on CMD.
